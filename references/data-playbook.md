# 取数手册（Wind MCP 实测）

配套工具：`mcp__wind-stock-data__get_stock_fundamentals`、`mcp__wind-stock-data__get_stock_basicinfo`。
两个工具都用**自然语言问句**取数，问句里必须同时出现：证券实体（名称或 Wind 代码）+ 指标 + 时间。

---

## 一、确定"近三年"是哪三年

以当前日期为准，取**最近三个已披露年报的完整会计年度**。

- 当年 4 月 30 日前（年报披露截止前），最新完整年度是「去年」；4 月 30 日后可用「去年」，但仍要确认返回的年份对不对。
- 核对工具返回的 `年份` 字段，与预期不一致时**以数据为准**，并在 `data_note` 说明（例如"2026 年数据尚未披露，报告区间为 2023–2025"）。
- 次新股上市不足三年 → 有几年给几年，`periods` 相应缩短，并在报告里说明。

---

## 二、四个问法模板（可直接复制替换公司名）

### 模板 1｜三家财务指标（核心）

```
查询{公司A}({代码A})和{公司B}({代码B}) {Y1}-12-31、{Y2}-12-31、{Y3}-12-31 的营业收入、营业总收入同比增长率、归母净利润、归母净利润同比增长率、ROE、销售毛利率
```

**多公司一定要写在同一句里**，否则两次返回的列名集合不同，口径核对会出人命。

### 模板 2｜收入构成

```
查询{公司} {Y1}年、{Y2}年、{Y3}年年报的主营业务收入构成，按产品分类的收入金额和占比
```

想要分行业口径就把"按产品分类"换成"按行业分类"；想要分地区就换成"按地区分类"。

### 模板 3｜估值

```
查询{公司} {Y1}-12-31、{Y2}-12-31、{Y3}-12-31、{最新交易日}的PE(TTM)、PB，以及当前PE和PB的近三年历史分位数
```

`{最新交易日}` 用报告生成日的前一交易日，例如 `2026-10-28`。

### 模板 4｜公司档案

```
查询{公司}的上市板、WIND行业分类、主营业务简介
```

## 三、返回结构（实测）

返回体是 `{"data": {"data": [ {columns:[...], rows:[...]}, ... ]}}`，**数组里可能有多个块**，两种形态都要能处理：

**形态 A：单公司 + 多报告期 → 每个报告期一个块**

```
块1: [Wind代码, 证券简称, 2023年营业收入, 2023年归母净利润, 2023年营业总收入同比增长率, ...]
块2: 同上，列名年份换成 2024
块3: 同上，年份换成 2025
```

**形态 B：多公司 + 多报告期 → 一个块，宽表**

```
[Wind代码, 证券简称, 2023年营业收入, 2023年营业总收入同比增长率, ..., 2025年销售毛利率,
 记账本位币_3, 2025年ROE, ...]
```

注意形态 B 的两个特征：
- 列名顺序**没有规律**（2024 年的列可能排在 2023 年之前）；
- 重复列会被自动加后缀（`记账本位币_2`、`记账本位币_3`）。

**因此解析必须按"列名里的年份 + 指标关键词"匹配，绝不能按列下标取数。**

### 字段映射

| 返回列名特征 | JSON 字段 |
|---|---|
| `{年}年营业收入` | `revenue[i]` |
| `{年}年营业总收入同比增长率` | `revenue_yoy[i]` |
| `{年}年归母净利润` | `net_profit[i]` |
| `{年}年归母净利润同比增长率` | `net_profit_yoy[i]` |
| `{年}年ROE` | `roe[i]` |
| `{年}年销售毛利率` | `gross_margin[i]` |
| `{年}年末PE` | `valuation.pe[i]` |
| `{年}年末PB` | `valuation.pb[i]` |
| `{日}PE` / `{日}PB`（最新交易日那组） | `valuation.pe_now` / `pb_now` |
| `最新市盈率在过去3年的分位数` | `valuation.pe_pct` |
| `最新市净率在过去3年的分位数` | `valuation.pb_pct` |
| `{年}年每年主营项目名称` + `主营项目收入` + `主营产品收入占比` | `segments.items[]` |

收入构成是**长表**：每行一个项目，字段为 `年份`、`名次`、项目名称、收入、占比。取 `名次` 1–4 且名称非 `null` 的行。

## 四、坑（都踩过）

1. **分位数单位不统一。** 同一句问法，A 公司返回 `37.79`，B 公司返回 `0.9338`——一个是百分数一个是小数。脚本 `norm_pct()` 会自动识别，但填入 JSON 前最好自己看一眼数量级，别把 0.93 当 0.93%。

2. **年末估值会缺年份。** 跨年时 `{Y3}年末PE` 可能整列缺失（返回里只有 Y1、Y2 年末）。此时该位置填 `null`，脚本会画成破折号；`pe_now` 仍可从分位数块里的"近3年每日PE"取到。**不要拿 `pe_now` 顶替年末值**。

3. **收入占比合计常常超过 100%。** 因为"其他业务"与主营项目重复计入（茅台 2023 年三项合计 102.3%）。照原样填，脚本归一化绘制。文字说明里要写清"占比合计可能超 100%"。

4. **多公司一次查询，某家公司的指标可能整列为空。** 不要用另一家的值补，也不要用 `0` 占位——写 `null` 并触发下面的复核流程。

5. **同比绝对值超过 30% 必须复核。** 换更短的问法再问一次（例如只问"XX 2025 年年报的营业收入和归母净利润"），确认是真实数据还是报告期错配。若两次一致但明显违背行业常识，写入 `data_note` 标注"数据待复核"，并在正文里对这一项保持克制，不要据此下强判断。

6. **金融股没有毛利率。** 银行、保险、券商的 `销售毛利率` 通常为空，用 `ROE` + 净利率替代；收入构成口径也不同（利息净收入、手续费、保费），`dimension` 写实际口径名称。图 3 若数据为空，直接省略该模块，不要画空图。

7. **港股 / 美股币种不同。** 看返回的 `记账本位币` 字段（CNY / HKD / USD）。金额按币种标注，不要混着说"亿"。

8. **工具偶发无响应或返回空。** 换更短、更口语的问法重试一次即可；仍为空就降级：缺哪块少哪块，在 `data_note` 说明，不要用记忆里的数字硬填。

## 五、交付前自检

- [ ] `periods` 长度 == 四个指标数组长度
- [ ] 每家公司都拿到了：营收、净利、两个同比、ROE、毛利率
- [ ] 净利增速与营收增速的背离，在正文里有解释
- [ ] `pe_pct` / `pb_pct` 数量级正常（0–100）
- [ ] 收入构成前 3 项名称不是 `null`
- [ ] 有 |>30%| 的同比时，已复核或已标注
- [ ] 报告渲染后没有空白图表模块
